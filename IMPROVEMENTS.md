# Swim — Что ещё можно улучшить

## Приоритеты

- **A** — заметное влияние на пользователя
- **B** — качество кода / архитектура
- **C** — nice to have

---

## 1. Множественные буферы и вкладки (A)

Сейчас `EditorWindow` хранит один `PieceTable`. При открытии нового файла старый теряется. Нет возможности переключаться между файлами без File Explorer.

**Решение:**
- Ввести `BufferManager` с массивом `(buffer: PieceTable, filePath: String?, modified: Bool, cursorState: ...)`
- `EditorWindow` отображает текущий активный буфер
- Tab bar в строке над редактором (как в VS Code)
- Горячие клавиши: `gt` / `gT` — следующий/предыдущий таб, `:bd` — закрыть таб

---

## 2. Incremental LSP sync (A)

При каждом нажатии клавиши вызывается `notifyLSPChange()`, который делает `buf.getAllText()` и отправляет **полный текст** файла в sourcekit-lsp. Для файла 100KB это создаёт 100KB+ JSON-RPC сообщение на каждый символ.

**Решение:**
- Хранить последний отправленный текст (или хотя бы длину)
- Отправлять `textDocument/didChange` с `range` вместо полного текста
- Или добавить debounce — отправлять не чаще чем раз в 100мс

---

## 3. Горизонтальная прокрутка и word wrap (A)

Длинные строки без пробелов (например URL, minified code) уходят за пределы экрана. Нет визуального переноса строк.

**Решение:**
- Режим `:set wrap` — soft wrap длинных строк с отступом продолжения
- `g$` / `g0` — прыжок к видимому концу/началу строки при wrap
- Показывать `>` в левом поле если строка выходит за экран

---

## 4. Система плагинов / конфигурация (A)

Нет файла конфигурации. Размер таба (2/4), тема, шрифт — всё захардкожено.

**Решение:**
- Файл `~/.config/swim/config.json` или `~/.swimrc`
- Настраиваемые параметры: `tabSize`, `showLineNumbers`, `wordWrap`, `theme`
- Маппинг клавиш: `nnoremap <key> <action>`
- Поддержка `.editorconfig` в проектах

---

## 5. Copy/paste через системный буфер обмена (A)

Сейчас `yank` копирует в внутренний буфер `yankBuffer`. OSC 52 копирование уже есть (`Terminal.osc52Copy`), ноpaste из системного буфера не реализован.

**Решение:**
- `Ctrl+Shift+V` или `"+p` — вставка из системного буфера
- Bracketed paste mode — корректная вставка многострочного текста из буфера

---

## 6. Миникарта / scrollbar (A)

Нет визуальной индикации положения в файле. В файлах >1000 строк непонятно, где находишься.

**Решение:**
- Вертикальная миникарта справа от редактора (как в VS Code / Sublime)
- Или хотя бы scrollbar indicator — тонкая полоска справа, показывающая позицию viewport

---

## 7. Find & Replace в текущем файле (A)

Поиск `/` работает, но замена `:%s/old/new/g` — только для текущей строки. Нет интерактивного find & replace.

**Решение:**
- `:%s/old/new/gc` — с подтверждением каждого replacement
- `*` — поиск слова под курсором
- Подсветка всех вхождений поиска (не только переход)

---

## 8. Split windows (A)

Нет возможности разделить экран горизонтально или вертикально для одновременного просмотра двух файлов (или двух мест одного файла).

**Решение:**
- `:sp` / `:vsp` — horizontal / vertical split
- `Ctrl+w w` — переключение между панелями
- Каждая панель — отдельный viewport в тот же или другой буфер

---

## 9. Incremental search с подсветкой (A)

Поиск `/query` не показывает совпадения до нажатия Enter. Нет подсветки всех вхождений.

**Решение:**
- При вводе в `/` сразу подсвечивать совпадения в редакторе
- Показывать количество совпадений: `[3/15]`
- `*` и `#` — поиск слова под курсором вперёд/назад

---

## 10. Автодополнение (A)

Нет автодополнения. sourcekit-lsp уже подключён и поддерживает `textDocument/completion`.

**Решение:**
- В insert mode при вводе запрашивать `textDocument/completion` у LSP
- Показывать popup с вариантами
- Tab / Enter — принять, Esc — отменить
- LSP completion уже есть в protocol — нужно только реализовать UI

---

## 11. Diagnostic подсветка (B)

LSP отправляет `textDocument/publishDiagnostics`, но `onDiagnostics` в LSPClient установлен, но не обрабатывается. Ошибки и предупреждения не показываются.

**Решение:**
- Подсветка ошибочных строк волнистой линией (через underline + красный цвет)
- Показывать диагностическое сообщение при наведении / в status bar
- Quick-fix list: `:cope` / `:copen` — список всех diagnostics

---

## 12. Кеширование токенов по viewport (B)

При каждом кадре токены запрашиваются заново — для builtin tokenizer это вызов `tokenize()` для каждой видимой строки. При прокрутке на 1 строку перетокенизируется весь viewport.

**Решение:**
- Кешировать токены по `(lineNum, lineContentHash)`
- Инвалидировать только при изменении содержимого строки
- Для LSP-токенов кешировать до следующего `semanticTokens/full` ответа

---

## 13. Отложенный рендеринг / dirty regions (B)

Сейчас при любом нажатии клавиши вызывается `updateAllWindows()`, который обновляет cell-буфер каждого видимого окна. Даже если изменился только один символ, перезаполняется весь экран.

**Решение:**
- Отслеживать dirty region: `dirtyRect` вместо `dirty: Bool`
- Обновлять только изменённые строки в cell-буфере
- Пропускать `update()` для окон, где ничего не изменилось

---

## 14. Piece Table: слияние смежных pieces (B)

При множественных вставках/удалениях pieces фрагментируются. Массив `pieces` может содержать тысячи элементов, замедляя `findPieceAndLocalOffset()` (линейный поиск).

**Решение:**
- Периодическое слияние смежных pieces из одного буфера
- Или замена массива на B-tree / rope для O(log n) поиска
- Лимит на количество pieces: при превышении — дефрагментация

---

## 15. Piece Table: line index как B-tree (B)

`lineStarts` — плоский массив. При вставке/удалении перестраивается от точки изменения. Для больших файлов это O(n) в худшем случае.

**Решение:**
- Структура данных на основе B-tree для O(log n) вставки/удаления в line index
- Или gap buffer для lineStarts (cache-friendly)

---

## 16. Поддержка мыши (B)

Нет обработки mouse events. Терминалы отправляют mouse events через CSI-последовательности при включённом режиме.

**Решение:**
- Включить mouse tracking: `\e[?1000h` (basic) / `\e[?1002h` (button event tracking)
- Парсить mouse events в `Key.parse()`
- Поддержка: клик для позиционирования курсора, scroll для прокрутки, drag для выделения

---

## 17. Syntax highlighting: multi-line comments и строк (B)

Встроенный tokenizer обрабатывает только `/* */` в пределах одной строки. Multi-line комментарии и строки не отслеживаются.

**Решение:**
- Хранить состояние (inComment, inString) между строками
- Аналогично markdown code block кешированию — передавать состояние от предыдущей строки

---

## 18. Поддержка .editorconfig (B)

Нет чтения `.editorconfig` для определения настроек проекта (tab size, trailing newline, charset).

**Решение:**
- Парсить `.editorconfig` при открытии файла из корня проекта
- Применять `indent_style`, `indent_size`, `end_of_line`, `trim_trailing_whitespace`
- Использовать в `indentSize()` вместо захардкоженного switch

---

## 19. Diff gutter markers (B)

Нет visual indicators в gutter (область номеров строк) для изменённых/добавленных/удалённых строк.

**Решение:**
- Хранить исходное содержимое файла при открытии
- Сравнивать текущие строки с оригинальными
- Показывать `+` / `~` / `-` в gutter для added/modified/deleted строк

---

## 20. Асинхронное чтение файла (B)

`PieceTable.fromFile()` читает файл синхронно через `Data(contentsOf:)`. Для файлов >10MB это вызывает задержку.

**Решение:**
- Чтение через `FileHandle` + chunked loading
- Показывать progress indicator для больших файлов
- Или memory-mapped I/O (`mmap`) — файл не загружается в память целиком

---

## 21. Tree-sitter вместо regex tokenizer (C)

Встроенный `SyntaxTokenizer` — линейный regex-like парсер. Не понимает контекст (например, ключевое слово внутри строки).

**Решение:**
- Интеграция tree-sitter через C-библиотеку
- Полноценное AST-based подсвечивание
- Incremental parsing при редактировании

---

## 22. Workspaces / projects (C)

Нет концепции проекта. CWD используется как корень для File Explorer и Search.

**Решение:**
- Файл `.swim.json` в корне проекта
- Настройки проекта: excluded dirs, file patterns, build command
- Workspace: набор открытых файлов, позиций курсоров, вкладок
- Восстановление сессии при повторном открытии

---

## 23. Встроенный терминал (C)

Нет встроенного терминала для выполнения команд без выхода из редактора.

**Решение:**
- Псевдотерминал (pty) через `forkpty()` / `openpty()`
- Terminal panel внизу экрана (toggle через горячую клавишу)
- Интеграция с shell: `$ command` в command mode

---

## 24. Marks и registers (C)

Нет vim marks (`m{a-z}` — установить mark, `'{a-z}` — перейти к mark). Нет named registers (`"a` — register a).

**Решение:**
- Локальные marks (a-z) — привязаны к файлу
- Глобальные marks (A-Z) — привязаны к файлу + позиции
- Named registers (a-z) для множественных буферов копирования

---

## 25. Macros (C)

Нет записи и воспроизведения макросов (`q{a-z}` — начать запись, `q` — остановить, `@{a-z}` — воспроизвести).

**Решение:**
- Записывать последовательность Key events
- Воспроизводить через `@{register}`
- `@@` — повторить последний макрос

---
