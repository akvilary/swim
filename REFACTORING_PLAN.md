## Фаза 1: Критические исправления (P0)

### 1.1 Убрать двойной вызов updateAllWindows
- **Файл:** `Application.swift:100-101, 399-400`
- **Проблема:** `run()` вызывает `updateAllWindows()`, затем `render()`, который внутри снова вызывает `updateAllWindows()`. Каждое окно обновляется дважды за кадр.
- **Решение:** Убрать `updateAllWindows()` из `render()`, оставить только в `run()` и местах где это нужно.

### 1.2 Исправить обработку SIGWINCH (resize терминала)
- **Файл:** `Terminal.swift:8, 38-46`, `Application.swift`
- **Проблема:** Обработчик сигнала пустой. `handleResize()` существует, но нигде не вызывается. Изменение размера терминала не обрабатывается.
- **Решение:** Реализовать передачу сигнала через pipe. В `Application.run()` проверять флаг resize и вызывать `recalculateLayout()` + `markAllDirty()` + `render()`.

### 1.3 Исправить потоконебезопасность CommandWindow
- **Файл:** `CommandWindow.swift:3-4`
- **Проблема:** Глобальные `nonisolated(unsafe)` переменные без синхронизации — race condition.
- **Решение:** Использовать `DispatchQueue` с барьерами или `NSLock` для защиты доступа к `_cmdResult`/`_cmdDone`. Либо передавать результат через callback из фонового потока через `DispatchQueue.main.async`.

### 1.4 Исправить isWideChar для CJK
- **Файл:** `Application.swift:464-470`
- **Проблема:** Проверяется только `first >= 0xF0` (4-байтные). CJK символы из диапазона U+0800–U+FFFF (3-байтные, 0xE0–0xEF) пропускаются.
- **Решение:** Добавить проверку `first >= 0xE0` с учётом диапазонов CJK: 0xE0..0xEF где конкретные codepoints имеют width=2. Использовать `wcwidth` или таблицу диапазонов.

## Фаза 2: Баги и корректность (P1)

### 2.1 Показывать ошибку при неудачном сохранении
- **Файл:** `EditorWindow.swift:224-231`
- **Проблема:** `catch {}` глотает ошибки.
- **Решение:** Добавить состояние `lastError: String?` в EditorWindow, показывать ошибку в StatusBarWindow.

### 2.2 Удалить мёртвый код Window.render()
- **Файл:** `Window.swift:80-103`
- **Проблема:** Метод `render(to:prevCells:)` определён, но нигде не вызывается.
- **Решение:** Удалить метод.

### 2.3 Почистить LSPProtocol.swift от неиспользуемых типов
- **Файл:** `LSP/LSPProtocol.swift`
- **Проблема:** Большинство Codable-структур не используются (LSPClient работает через `[String: Any]`).
- **Решение:** Удалить неиспользуемые типы: `LSPRequest`, `LSPNotification`, `LSPResponse`, `LSPInitializeParams`, `LSPClientCapabilities`, и т.д. Оставить только `SemanticToken`.

### 2.4 Удалить недостижимую проверку в tokenizer
- **Файл:** `SyntaxTokenizer.swift:176-177`
- **Проблема:** `word.hasPrefix("//")` в блоке идентификаторов — `/` не входит в множество символов идентификатора, условие никогда не истинно.
- **Решение:** Удалить ветку.

### 2.3 Исправить Number parsing в tokenizer
- **Файл:** `SyntaxTokenizer.swift:161-167`
- **Проблема:** Слишком жадный парсинг чисел — символы `a-f` захватываются всегда, даже вне hex-контекста.
- **Решение:** Различать hex (`0x` prefix) и десятичные числа. Для hex разрешить `a-f`, для остальных — только `0-9`, `.`, `e`, `_`.

## Фаза 3: Производительность (P1)

### 3.1 Индекс токенов по словарю
- **Файл:** `EditorWindow.swift:697-699`
- **Проблема:** `semanticTokens.filter { $0.line == line }` — O(n) на каждую строку каждого кадра.
- **Решение:** При установке `semanticTokens` строить `[Int: [SemanticToken]]` индекс. Метод `semanticTokensFor(line:)` станет O(1).

### 3.2 Плоский массив для prevScreenCells
- **Файл:** `Application.swift:22`
- **Проблема:** `[Int: [Int: Cell]]` — двойной хеш-лукап на каждую ячейку.
- **Решение:** Заменить на `[Cell?]` размером `terminal.width * terminal.height`. При resize — пересоздавать.

### 3.3 Кешировать markdown tokenizer state
- **Файл:** `SyntaxTokenizer.swift:222-246`
- **Проблема:** Каждый кадр перечитывается до 500 строк для отслеживания inCodeBlock.
- **Решение:** Кешировать состояние code block между вызовами, инвалидировать при изменении scrollY/буфера.

## Фаза 4: Undo/Redo (P1)

### 4.1 Реализовать Undo/Redo
- **Файл:** `EditorWindow.swift:29-30, 494-495`
- **Проблема:** `undo()`/`redo()` — пустые функции. Стеки объявлены, но не используются.
- **Решение:**
  - При каждой операции вставки/удаления записывать `(offset, deletedText, insertedText)` в `undoStack`
  - `undo()`: взять последнюю запись, удалить inserted, вставить deleted обратно, поместить в `redoStack`
  - `redo()`: взять из `redoStack`, повторить операцию
  - Любая новая операция очищает `redoStack`
  - Обёртки для insert/delete, которые фиксируют изменения

## Фаза 5: Асинхронные операции (P2)

### 5.1 Асинхронный поиск по проекту
- **Файл:** `SearchWindow.swift:99-132`
- **Проблема:** Синхронный обход файлов блокирует event loop.
- **Решение:** Запускать поиск в фоновой очереди, обновлять результаты через callback. Показывать spinner во время поиска.

### 5.2 Асинхронные git-операции
- **Файл:** `GitPanelWindow.swift:360-375`
- **Проблема:** `runGit()` блокирует main thread.
- **Решение:** Запускать git команды асинхронно, обновлять данные по завершении. Для quick ops (status, log) можно оставить синхронными если они < 100ms, но для stage/unstage/diff — асинхронно.

## Фаза 6: Рефакторинг архитектуры (P3)

### 6.1 Вынести Renderer
- **Проблема:** Рендеринг (prevScreenCells, termFG/BG, diff-based comparison) реализован в Application.
- **Решение:** Создать `Renderer` класс, инкапсулирующий: prevScreenCells, состояние терминальных атрибутов, логику diff-based рендеринга.

### 6.2 Вынести LayoutManager
- **Проблема:** Layout-логика в `recalculateLayout()` — часть Application.
- **Решение:** Создать функцию/структуру `LayoutManager`, принимающую список окон с их visibility и размер терминала, возвращающую прямоугольники для каждого окна.

### 6.3 Протокол WindowDelegate
- **Проблема:** Разрозненные closures: `onFileSelect`, `onResultSelect`, `onCommand`, `onRunCommand`, `onNeedsRender`.
- **Решение:** Определить `protocol WindowDelegate` с методами для всех событий окон. Application реализует протокол.
